# v0.1.0 — Local creator MVP

**Scope:** an owner-operated, loopback-only source release. The frozen workflow is **create → animate → compare → save → reopen → download**. No remote publication, public-service launch or research conclusion is included.

## Included workflow

- Import a still PNG, JPEG or WebP without changing the original bytes. Select parts manually with rectangle and add/erase brush tools; apply Rotate / sway, Pulse / scale or Move with intensity, speed and optional finite **Repeat movement**. **Advanced** retains custom movement fields, including affine-v2 scale/stretch; explicitly choosing scale or stretch upgrades the draft to version 2, while opening it does not migrate it.
- Use **Preview changes** to save, prepare and play the matching result once. **Before** is the previous successful preview or a labeled original fallback; **After** is the current result. Editing alone does not render. Stale results are labeled, and failures preserve the last valid result.
- Keep **Save draft** and save status in the header, **Undo / Redo** beside the canvas and the primary preview action at the bottom on narrow screens. Save without rendering; sign in and reopen saved work after restarting the service. Reopening never starts motion; reduced motion remains static.
- Choose **Download animation** beside Before/After for the exact current After WebM, without rerendering or transcoding. Before, stale edits and pending/invalid output cannot be downloaded as current. **Repeat movement** is encoded; **Loop preview (3 plays)** is UI playback only. The browser controls file saving, so “Download requested” is not saved-file proof.

Private accounts, chapter ordering and reviewed snapshots remain available, but guest sharing is not required for this local workflow. The separate research reader is unchanged by release scope.

## Supported local configuration and bounds

| Area | v0.1.0 boundary |
| --- | --- |
| Runtime | Node.js 22.12+, npm 11+, locked dependencies; Linux/procfs and existing `/snap/bin/ffmpeg` with VP9 encoding. No binary installer or automatic FFmpeg/model provisioning. |
| Persistent operation | Compiled account service through `local:configure`, `local:doctor` and `local:start`, on loopback with a dedicated private store outside the checkout. |
| Import | Still PNG/JPEG/WebP, at most 10 MiB and 20 million pixels per original. Animated, incomplete and unsupported files are rejected. |
| Working image | EXIF-oriented, white-flattened copy, maximum edge 1280 pixels; original bytes remain unchanged. |
| Rendering | At most six seconds, 24 fps, 16 parts and eight moving parts; positive scale/stretch factors from 0.75 to 1.25; finite WebM, not unlimited animation. |
| Processing | One active import per project store; render/inference admission shares one heavy-job slot per service process. Use one server process per account store. |
| Persistence | Private filesystem permissions, explicit stopped-writer backup/restore to fresh destinations; data and backups are not encrypted or automatically backed up. No schema-migration or cross-version compatibility promise. |

`npm run dev` uses a separate development-only store. `npm run preview` serves static build output and cannot save, process or reopen account data. Use the [runbook](../local-mvp-runbook.md) for persistent operation, verified source bundles, backup/restore and release replacement/rollback.

## Known limits and evidence boundary

- Optional model assistance is off in the persistent local launcher; manual creation, animation and playback do not require models. No model download or quality guarantee is included.
- Motion is bounded source-texture compositing, not generative animation or reconstruction of hidden artwork. Inspect your own output and downloaded file in a WebM-capable player.
- No Internet deployment, new content-rights clearance, varied-manga validation, physical-device proof, accessibility certification, machine-reboot proof or research result is claimed. Historical public-product/research decisions D1–D7 remain **OPEN**; they do not block the accepted owner-local scope.
- The [verification record](../local-mvp-verification.md) documents historical engineering checkpoints. The separate final release receipt must identify the exact candidate source and local tag; older receipts are not proof for changed source. Human acceptance remains the user's responsibility.

No dependencies, model assets or artwork are added by this version closure. Source delivery is a verifiable working-tree snapshot, not an npm publication or remote release.
